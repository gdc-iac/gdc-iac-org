# GDC Database Cluster Provisioning (008-PA-DB-CREATE)

This directory implements the Infrastructure-as-Code (IaC) pipeline for deploying a logical Database Cluster inside a GDC logical project container, mapping to standard split-privilege operational paradigms.

---

## 1. Architecture & Privileges

To prevent unauthorized access and contain operational failure blast radius, the deployment is split into two clear day-of-work phases:

### Day-0: Elevated Setup (Platform Admin)
Before the application runner can provision a database, a physical GDC `BackupRepository` must be configured at the administrative level (databases in GDC require backup configurations to activate).
The elevated **`setup-adhoc-env.sh`** script handles this by:
* Creating the target mock S3 secret inside namespace `ioc-test-infra`.
* Deploying the cluster-scoped `BackupRepository` named `dbs-backup-repository`.
* Registers the restricted `test-runner-008-sa` ServiceAccount and assigns logical project roles.

### Day-1: Workload Runner (Application Operator)
The restricted **`test-runner-008-sa`** CI pipeline executes the Helmfile orchestrator:
* Provisions the logical project workspace (`Project` resource).
* Attaches project bindings to target user/admin clusters.
* Provisions the logical Postgres database cluster resource (`ioc-test-db`).

---

## 2. Step-by-Step Execution Guide

> [!IMPORTANT]
> **Support for Custom Environments**
> Like all platform-test cases, this folder supports dynamic environment variable overrides (`ORG_NAME` and `IAC_PROJECT`) to support execution on production-grade staging/prod hardware.

### Step A: Elevated Day-0 Bootstrap
Run the setup driver to provision database backup dependencies and build the runner credentials:
```bash
# (Optional) Export custom staging organization and project namespace:
export ORG_NAME="community"
export IAC_PROJECT="iac-staging"

# Run Day-0 Bootstrap
./setup-adhoc-env.sh
```

---

### Step B: Run Day-1 Workload Deployments
Use the compiled customer runner credential kubeconfig (generated by Step A) to execute the logical database provisioning plan:
```bash
# Target the customer runner context and logical namespace
export KUBECONFIG="../000-SETUP/.kubeconfigs/customer-sa-kubeconfig.yaml"
export ORG_NAME="community"
export IAC_PROJECT="iac-staging"

# Execute deployment
helmfile sync
```

---

## 3. Verification & Inspection

Once the pipeline finishes, you can verify that the database cluster is running inside its dedicated project boundary:

```bash
# View the Postgres cluster status
kubectl --kubeconfig="$KUBECONFIG" --context=runner-context \
  get dbclusters.postgresql.dbadmin.gdc.goog -n ioc-test-project-008
```
